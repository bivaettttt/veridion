# Veridion · Кейс для портфолио системного аналитика

| Этап | Материал для кейса |
| --- | --- |
| Задача | Исследователь проверяет, подтверждает ли документация техническую характеристику. Редакции меняются, а одинаковые цифры могут относиться к требованиям и измерениям. |
| Мой вклад | Задал продуктовую концепцию, приоритеты и критерии приёмки. Связи между версиями, цитатами и решениями описаны в аналитических артефактах проекта. Код и документация подготовлены с помощью Codex. |
| Требования | Проектная изоляция, историю версий можно воспроизвести, каждый аналитический вывод проверяется по тексту, ручное решение остаётся в журнале. |
| Архитектура | Модульный FastAPI, отдельный worker, PostgreSQL/pgvector, версионные ссылки и снимки, гибридное ранжирование, локальная генерация с проверкой ссылок. |
| Реализация | Библиотека источников, исследовательский экран, инспектор цитат, сравнение свидетельств, очередь согласования, отчёты и лаборатория на PostgreSQL. |
| Проверка | API и Playwright, многоязычный поиск, конкурентное согласование, отказ провайдера, проверка цитат и отдельный запуск локальной модели. |
| Результат | Veridion воспроизводит ключевой сценарий Northstar. Требование 10 000 пользователей и наблюдение при 2 000 представлены как разные виды доказательств. |

Демонстрация на собеседовании. Сначала запустите предзаполненный вопрос, откройте и проверьте цитату, затем покажите редакцию документа. Для архитектурного обсуждения откройте два измерения доступности, журнал согласования и снимки отчёта. Для тестового обсуждения выполните лабораторию и откройте сценарии неверной версии или отказа локальной модели.
